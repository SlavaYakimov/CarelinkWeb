# e2e-flow-map

Вход: flow от пользователя (имя и/или шаги), `recon.md`.
Выход: `flow.md`.

## Шаги

1. Если пользователь дал шаги — проверь каждый по коду (`recon.md` → маршруты / формы). Расхождение между словами пользователя и кодом — в отдельную секцию «Расхождения». Не молчи и не правь шаги самовольно.
2. Если дал только имя — восстанови шаги из кода: от точки входа до финального URL / состояния. Пометь, что шаги восстановлены, а не заданы.
3. На каждый шаг заполни строку:

| # | URL | Предусловие (сессия / cookie / данные) | Действие | Ожидаемый результат | Компонент / action `file:line` | Существующая cy-команда |

4. Ветвления внутри flow (ошибка backend, невалидные данные, таймер) — перечисли как «Боковые выходы» с ожидаемым поведением по коду формы, без тестов.
5. Compose: нужен ли живой backend (OTP, создание сущности) — да / нет и что именно.
6. Секция «Не покрыть сейчас»: шаги, упирающиеся в BE-xx из `docs/web-screens-status.md`, или в отсутствие тестовых данных.

## Не делай

- Не выдумывай ожидаемое поведение. Если код не определяет, что должно быть, — пиши «не определено кодом, нужно решение» и ссылку на место.
- Не добавляй другие flow. Только заданный.
- Не меняй файлы репозитория.

## Формат `flow.md`

`## Flow` (имя, источник: задан / восстановлен) · `## Шаги` (таблица) · `## Расхождения` · `## Боковые выходы` · `## Compose` · `## Не покрыть сейчас`. Пустые секции помечаются словом «пусто».

## Готово, когда

Каждая строка таблицы шагов имеет `file:line`; присутствуют все шесть секций.

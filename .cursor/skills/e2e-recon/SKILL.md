# e2e-recon

Вход: имя flow, каталог артефактов `/tmp/e2e/<slug>/`.
Выход: `recon.md`.

## Собери (каждая строка — с `file:line` или выводом команды)

1. **Тесты**: `cypress/e2e/**`, `cypress/support/*.ts` — каждая custom-команда: имя, аргументы, какие селекторы/тексты использует, какие URL ожидает. `cypress.config.ts` — tasks, env, baseUrl. `scripts/e2e/*`. Скрипты `test:e2e*`, `cypress:*` в `package.json`.
2. **Маршруты**: все `page.tsx` в `src/app/(public)`, `src/app/(app)`, `src/app/api/**`, `proxy.ts` / `middleware.ts`. Для каждого — кто имеет доступ (гость / частичная сессия / полная) и куда редиректит без прав.
3. **Формы / actions**: `src/components/carelink/*`, `src/server/**` — поля, zod-схемы, коды ошибок и как они показываются в UI (`role="alert"`, текст).
4. **Сессия**: какие cookie выставляются на каждом шаге, где читаются, срок жизни, что при истечении.
5. **Доки**: `docs/PLAN.md` §6, `docs/web-screens-status.md` (секция «Пробелы backend»), `docs/ux/scenarios.md` — если файла нет, запиши «сценарии не задокументированы».
6. **Окружение — выполнить, не предполагать**: доступен ли `http://127.0.0.1:3000`; поднят ли compose (`docker ps`, команды из `AGENTS.md`: `../CarelinkAuth` → `make compose-web-e2e-up`); отвечает ли gateway. Вывод команд — в отчёт.

## Не делай

- Не читай и не цитируй значения cookie, токены, содержимое `.env*` — только имена переменных.
- Не предлагай тесты и не оценивай риски. Только факты.
- Не меняй файлы репозитория.

## Формат `recon.md`

Секции: `## Команды Cypress` · `## Маршруты` · `## Формы и ошибки` · `## Cookie и сессия` · `## Документация` · `## Окружение` — каждая таблицей.

## Готово, когда

`recon.md` содержит все шесть секций; каждая строка подкреплена `file:line` или выводом команды; секция «Окружение» содержит фактический результат проверок, а не предположение.

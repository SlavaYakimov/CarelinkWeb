# e2e-report

Вход: все артефакты `/tmp/e2e/<slug>/` (`recon.md`, `flow.md`, `risks.md`, `happy.json`, `break.json`).
Выход: `report.md`.

## Структура

1. **Flow и источник**: задан пользователем / восстановлен по коду; расхождения из `flow.md`.
2. **Покрытие**: шаг flow → тест → статус (`pass` / `fail` / `skip + BUG-n` / не покрыть, BE-xx).
3. **Findings** (из `happy.json` и `break.json`), каждый отдельно: ID · severity · шаги воспроизведения · имя теста · ожидаемое vs фактическое · `file:line` · frontend / backend · гипотеза причины и предложение исправления (без правок кода).
4. **Flaky и инфраструктура**: `flaky-under-noise`, зависимость от compose, что не поднялось локально, что остаётся в БД после прогона и как чистить.
5. **Не проверено и почему**: риски с `test: null`, шаги из «Не покрыть сейчас».
6. **Команды**: полный прогон, compose-часть, один спек, шумный прогон — дословно, готовые к копированию.
7. **Проверка**: вывод `pnpm lint && pnpm typecheck` по изменённым файлам; список спеков с итогом `cypress run`.

## Правила

- Каждое утверждение — с доказательством (`file:line`, имя теста, вывод команды). Без доказательства — в секцию «Предположения».
- В отчёт не попадают значения токенов, cookie, телефонов, кодов, паролей.
- Отчёт не кладётся в репо без явной просьбы пользователя.

## Готово, когда

Все 7 секций заполнены (или помечены «пусто»); число findings в отчёте совпадает с суммой `bugs` в `happy.json` + `break.json`.

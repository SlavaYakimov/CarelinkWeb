# Carelink Web — карта экранов и переходов

Источник: /workspace/carelink-guide (16 сценариев, API reference) + правила продукта. Платформа: web (desktop-first, адаптив). Язык UI: русский.

Правила, отражённые в потоке:
- Вход **только** через Carelink Workspace (`slug@workspaces.carelink.app` + личный пароль). Персональный вход по email (scn-personal, `/v2/auth/personal/sign-in/*`) намеренно не используется.
- Приглашение: хранитель вводит личную почту + телефон; письмо уходит на личную почту. Новый → workspace-логин + одноразовый временный пароль (72 ч, обязательная смена, `TEMP_PASSWORD_EXPIRED`). Существующий → пароль не меняется, принимает приглашение после входа (7 дней). Хранитель видит, зарегистрирован ли email (`lookup-email`).
- verify-phone после логина; регистрация устройства по `deviceRegistrationToken` (онбординг).
- Заявки на вступление, восстановление и delegate-вход подтверждает только реальный хранитель этой семьи (экран 28).
- Push-доставка (scn-push) и OTP (scn-otp) — системные/встроенные шаги, отдельных экранов нет: они проявляются в 06/07/08/12/13/25/30 и центре уведомлений 39.

## A. Вход через Workspace (scn-ws-signin, scn-otp, scn-device)

| № | Экран | Назначение | Переходы |
|---|---|---|---|
| 01 | 01 Вход — Workspace | Единственный вход: workspace-логин семьи + личный пароль. | 02 | 02 Вход — неверный пароль | Состояние ошибки входа. Один и тот же текст для неверного пароля и отсутствия членства (сервер не раскрывает причину). | → 01 (повторить); → 29 (восстановить через семью); → 03 (лимит исчерпан) |

## Глобальные переходы

- Любой защищённый экран: access истёк → `POST /v1/auth/token/refresh` (ротация); 401 → 40 «Сессия завершена»; аккаунт заблокирован → 32.
- Любой экран: 429 → 03 (или inline-таймер); 5xx `*_UNDELIVERED` → inline-баннер «Не удалось отправить, повторите».
- Сайдбар приложения: Главная 33, Семья 34, Приглашения 20/21, Заявки 27, Уведомления 39, Профиль 37, Устройства и сессии 38, Безопасность 36.
